# 🔌 MediMind — API & Microservice Architecture

This is the version we should use going forward.

---

## 1. Final Microservices

MediMind will have **9 components**:

```text
1. 🚪 API Gateway
2. 🔐 Auth Service
3. 👨‍👩‍👧 Family Service
4. 🏥 Hospital Service
5. 👨‍⚕️ Doctor Service
6. 📅 Appointment Service
7. 🗂️ Medical Record Service
8. 🤖 AI Prediction Service
9. 📚 Knowledge Service
```

And:

```text
1 MongoDB Atlas Deployment
        │
        ├── medimind_auth
        ├── medimind_family
        ├── medimind_hospital
        ├── medimind_doctor
        ├── medimind_appointment
        ├── medimind_records
        ├── medimind_ai
        └── medimind_knowledge
```

Each service owns its own logical database.

# 3. API Gateway

### Port

```text
5000
```

### Responsibility

The Gateway is the **single entry point** for the frontend.

It handles:

* Request routing
* JWT verification
* Authentication information
* Role-based access checks
* Request forwarding
* Centralized error responses

It does **not** contain medical/business logic.

### Example

Frontend:

```http
GET /api/families/members
```

Gateway forwards to:

```text
Family Service
GET /families/members
```

# 9. The Correct Appointment Workflow

This is extremely important.

Every appointment requires an AI prediction.

```text
Family
   ↓
Select Patient
   ↓
Choose Doctor
   ↓
Choose Date & Time
   ↓
Book Appointment
   ↓
AI Prediction Required
   ↓
AI Prediction Service
   ↓
Prediction Created
   ↓
Prediction linked to Appointment
   ↓
Doctor sees Appointment + AI Prediction
   ↓
Consultation
   ↓
Prescription
```

The relationship is:

```text
Appointment
     │
     └── ai_prediction_id
```

# 11. AI Can Be Used Independently

This is another finalized rule.

A patient **does not need an appointment** to use AI.

For example:

```text
Family
 ↓
Select Patient
 ↓
AI Predictions
 ↓
Diabetes Risk
 ↓
Enter health parameters
 ↓
Prediction
```

Here:

```text
appointment_id = null
```

---

# 12. AI Can Also Be Used For an Appointment

For an appointment:

```text
appointment_id = actual appointment ID
```

So the same prediction system supports both:

```text
Independent Prediction
        │
        └── appointment_id = null


Appointment Prediction
        │
        └── appointment_id = <appointment>
```

---

# 13. General Health AI

The fourth AI module accepts text.

Example:

```text
"Having 103°F temperature, headache and body pain since yesterday."
```

API:

```http
POST /api/ai/general-health
```

The AI returns things such as:

```text
Possible concerns
Urgency indication
General guidance
Medical evaluation recommendation
```

It should **not** say:

```text
"You have disease X."
```

Instead:

```text
"Possible concerns include..."
"Medical evaluation is recommended."
```

```text

   ↓

   ↓

   ↓

   ↓

```


# 17. 🔐 Doctor Medical-Record Access

There is **no separate Doctor Access microservice**. Access authorization is a feature of the Medical Record Service.

The family explicitly grants a doctor full access to the records of a selected family member.

```text
Family Account
      ↓
Select Family Member
      ↓
Choose Doctor
      ↓
Grant Full Access
      ↓
RecordAccess
      ↓
Doctor
      ↓
Complete Records of Selected Member
```

The access model is all-or-nothing for the selected family member.

There are no individual permission checkboxes such as:

```text
☐ Reports
☐ X-rays
☐ Prescriptions
☐ Consultations
```

### Record Access APIs

```text
POST /api/records/access
GET  /api/records/access/member/:memberId
PUT  /api/records/access/:accessId/revoke
GET  /api/records/access/doctor/me
```

The family can view current authorized doctors and revoke access. The doctor can view their own access history.

# 22. Service-to-Service Communication

Services **never directly access another service's database**.

For example:

### ❌ Wrong

```text
Doctor Service
      ↓
medimind_family database
```

### ✅ Correct

```text
Doctor Service
      ↓ HTTP/REST
Family Service
      ↓
medimind_family
```

Similarly:

```text
Appointment Service
        ↓ REST
AI Prediction Service
```

and:

```text
Medical Record Service
        ↓ REST
Doctor Service
```

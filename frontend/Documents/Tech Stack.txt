# 🗄️ 3. Database

### Database Technologies

* MongoDB
* MongoDB Atlas
* Mongoose

### Database Architecture

MediMind will use:

**One MongoDB Atlas deployment with separate logical databases for each microservice.**

```text
                         MongoDB Atlas
                              │
       ┌──────────────┬───────┼────────┬──────────────┐
       ↓              ↓       ↓        ↓              ↓
medimind_auth   medimind_family  medimind_hospital
       │              │              │
     users      families/members   hospitals/
                                  departments/
                                  department_heads

       ↓              ↓              ↓
medimind_doctor   medimind_appointment
       │                  │
    doctors          appointments

              ↓
       medimind_records
              │
       ┌──────┼──────────┐
       ↓      ↓          ↓
    records consultations prescriptions
                     │
                     ↓
                record_access

              ↓
        medimind_ai
              │
         predictions

              ↓
      medimind_knowledge
              │
           articles
```

### Logical Databases

```text
medimind_auth
└── users

medimind_family
├── families
└── family_members

medimind_hospital
├── hospitals
├── departments
└── department_heads

medimind_doctor
└── doctors

medimind_appointment
└── appointments

medimind_records
├── medical_records
├── consultations
├── prescriptions
└── record_access

medimind_ai
└── predictions

medimind_knowledge
└── articles
```

### Database Communication Rule

Microservices **must not directly access another service's database**.

Cross-service communication uses:

```text
Service A
   ↓
REST API
   ↓
Service B
   ↓
Service B Database
```

Mongoose `populate()` is used only for relationships within the same service/database.

# 👨‍⚕️ 6. Human-in-the-Loop AI

MediMind AI is designed as **clinical decision support**, not autonomous diagnosis.

```text
Patient
   ↓
Medical Data
   ↓
AI Model
   ↓
AI-Assisted Prediction
   ↓
AI Explanation
   ↓
Doctor
   ↓
Clinical Assessment
   ↓
Final Decision
```

For appointments:

```text
Appointment
     ↓
Required AI Prediction
     ↓
AI Result
     ↓
Doctor Reviews Result
     ↓
Consultation
     ↓
Prescription
```

Independent AI predictions can also be performed without an appointment.

# 🚪 10. API Gateway

The API Gateway acts as the **single entry point** for the frontend.

```text
React Frontend
      ↓
  API Gateway
      ↓
 ┌────┼─────┬────────┬────────┐
 ↓    ↓     ↓        ↓        ↓
Auth Family Hospital Doctor Appointment
                         │
                         ↓
                  Medical Records
                         │
                ┌────────┴────────┐
                ↓                 ↓
              AI              Knowledge
```

Responsibilities:

* Route API requests
* Forward requests to appropriate microservices
* Centralize backend entry point
* Support authentication/authorization flow
* Hide internal service structure from the frontend

```text
Family
Doctor
Department Head
Hospital Admin
Chairman
```

# 📦 12. File / Medical Record Handling

Medical records such as:

* Reports
* Tests
* X-rays
* Scans
* ECGs
* Prescription documents
* Other medical documents

will be managed through the **Medical Record Service**.

The database stores record metadata and file references rather than placing large files directly inside normal MongoDB documents.

MEDIMIND — FRONTEND DESIGN SYSTEM, COLORS & PAGE DESIGNS
==========================================================

Document Purpose
----------------
This document defines the common React frontend visual system and the page-level
design for every MediMind page.

Frontend stack:
- React.js
- JavaScript
- Tailwind CSS
- React Router
- Axios

Design goals:
- Professional healthcare appearance
- Clean and modern SaaS dashboard
- High readability
- Consistent role-based navigation
- Responsive desktop/tablet/mobile layouts
- Accessible contrast and clear status indicators

10. RESPONSIVE DESIGN
---------------------

Desktop:
- Fixed/collapsible sidebar
- Topbar
- Multi-column cards
- Data tables

Tablet:
- Collapsible sidebar
- Two-column cards
- Responsive tables

Mobile:
- Drawer navigation
- Single-column cards
- Stacked forms
- Horizontal tab scrolling where required
- Large touch targets

11. ACCESSIBILITY
-----------------

- Use semantic HTML.
- Maintain strong text/background contrast.
- Every input has a label.
- Buttons must have meaningful labels.
- Images need alt text.
- Do not rely only on color to communicate status.
- Keyboard navigation should be supported.
- Loading and error states should be visible.
- Destructive actions require confirmation.

12. GLOBAL UI STATES
--------------------

Every data-driven page should support:
- Loading state
- Empty state
- Error state
- Success feedback
- Validation state
- Unauthorized/forbidden state

Examples:
Loading:
"Loading your medical records..."

Empty:
"No records available for this family member."

Forbidden:
"You do not have permission to access this information."

13. PRIVACY-AWARE UI
--------------------

The selected family member must always be visually clear when family users
are working with:
- Medical Records
- AI Predictions
- Appointments
- Consultations
- Prescriptions
- Doctor Access

Doctor pages must clearly identify the currently selected authorized patient.

Organizational hierarchy must never be represented as automatic access to private
medical records.

15. FINAL FRONTEND DESIGN PRINCIPLE
-----------------------------------

MediMind should look like a professional healthcare SaaS platform rather than
a generic student dashboard.

Core visual hierarchy:
- Deep Indigo/Sapphire = navigation, primary actions, identity
- Teal = positive healthcare/active states
- Blush Pink = restrained accent
- Amber = warnings/pending states
- Red = errors/destructive/high-urgency states
- White/Slate = clean content surfaces

The design should remain consistent across all five roles while allowing each
role to emphasize its own workflow.
